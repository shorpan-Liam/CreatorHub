## 2. 日常启动

推荐直接双击项目根目录的 [一键启动.bat](../一键启动.bat)。脚本自动切换到项目路径，构建前端、准备数据库并启动 API 与 worker；健康检查通过后打开默认浏览器。已经正常运行时直接打开网站，失败时保留窗口供查看错误。关闭启动窗口或浏览器不会停止后台服务。

修改代码后先按下方命令停止应用，再双击启动。自动化验证可使用 `一键启动.bat -NoBrowser`，只启动和检查服务，不打开浏览器。本机 PostgreSQL 服务需要处于运行状态。

也可继续使用原有命令：

```powershell
Set-Location 'F:\Project\CreatorHub'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start.ps1
```

此命令构建前端、执行数据库迁移和幂等种子，然后以隐藏窗口启动 API 与 worker。

启动前会先实际启动一次 Playwright Chromium 做检查。若检查失败，在项目根目录执行 .venv\\Scripts\\python.exe -m playwright install chromium；安装完成后重新启动。不要使用系统 Python 或 Conda Python 安装浏览器，否则浏览器文件可能落到另一套 Python 环境。

- 网站：`http://127.0.0.1:8000`
- API 文档：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/api/v1/health/ready`
- 前端已经构建且未修改时，可添加 `-SkipBuild`。
- 启动脚本遇到已运行的进程或占用的 8000 端口会报错，不会强制结束未知进程。

停止应用：

```powershell
Set-Location 'F:\Project\CreatorHub'
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\stop.ps1
```

只停止已记录且校验 PID、可执行路径和启动时间的项目进程；不会停止系统 PostgreSQL 服务。生成中的任务如被中断，下次 worker 启动后按租约恢复。

## 3. 开发前端

`scripts\start.ps1 -Dev` 额外启动 5173 端口的 Vite。先停止旧的项目进程再执行。

- UI 开发访问 `http://127.0.0.1:5173`，`/api` 自动代理到 8000。
- 截图 worker 始终加载 8000 的固定构建；修改模板后执行 `npm.cmd run build`。
- 变更构建期间正在生成的任务可能提示版本变化，重新生成即可。
- 开发服务器不要混用 localhost 和 127.0.0.1，以保持匿名 Cookie 与草稿来源一致。

## 4. 在新的环境安装

已配置的本机无需重复安装。迁移项目时：

```powershell
Set-Location 'F:\Project\CreatorHub'
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.lock.txt
.\.venv\Scripts\python.exe -m playwright install chromium
Set-Location frontend
npm.cmd ci
```

复制 `backend/.env.example` 为 `.env`，填写专用数据库连接。不要提交真实密码。

如需在现有 PostgreSQL 中初始化专用角色及空数据库，可在终端设置 `PGUSER`、`PGPASSWORD`（管理员已有凭证），然后执行 `scripts/setup_database.py`。脚本只允许在 `creatorhub_app`、`creatorhub`、`creatorhub_test` 均不存在时初始化，不重置既有角色、不覆盖数据库。使用后清除终端环境变量。

本项目不使用 Docker、Redis 或 Node 业务后端。数据库之外的临时文件放在 `storage/files/`。

## 5. 自动测试

后端：

```powershell
Set-Location 'F:\Project\CreatorHub\backend'
..\.venv\Scripts\python.exe -m pytest -q
```

测试读取 `.env` 中的 TEST_DATABASE_URL，强制数据库名为 `creatorhub_test`。覆盖数据校验、匿名隔离、图片上传、幂等、队列并发领取、租约回收和取消。

前端：

```powershell
Set-Location 'F:\Project\CreatorHub\frontend'
npm.cmd test
npm.cmd run build
```

真实出图验证（API、worker 必须已运行）：

```powershell
Set-Location 'F:\Project\CreatorHub'
.\.venv\Scripts\python.exe scripts\verify_render.py
```

该脚本用原创测试文本创建匿名任务，验证长段落、带 Logo 的高版 JPG、手动分页、仅标题和超长标题报错，逐页检查像素尺寸、正文范围、ZIP 文件一致性。报告写入 `storage/render-verification.json`。只连接本机服务，HTTP 客户端禁用环境代理，避免本机请求被系统代理转发。

## 6. 日志与存储

| 路径 | 内容 |
| --- | --- |
| `storage/api.stdout.log`、`api.stderr.log` | HTTP 访问和 API 错误 |
| `storage/worker.stdout.log`、`worker.stderr.log` | 任务 ID、阶段错误码，不记录正文 |
| `storage/processes.json` | 启动脚本管理的进程记录 |
| `storage/files/assets/` | 清理过元数据的临时 Logo |
| `storage/files/renders/` | 每任务每尝试的图片及 ZIP |
| `storage/test-files/` | 测试资源 |

临时渲染结果默认保留 24 小时，数据库任务最小记录保留 7 天。本机草稿位于浏览器 IndexedDB，不在服务器数据库；清理浏览器数据前应导出项目备份。

## 7. 已知环境事项

- Windows 下使用同步 Playwright 的独立 worker，避免 API 事件循环与浏览器子进程相互影响。
- 本机已有的 Python 包索引连接不稳定，首次安装切换为官方 PyPI 成功；如再次遇到超时，可指定 `--index-url https://pypi.org/simple`。
- 初期曾准备 55432 的项目独立 PostgreSQL；根据用户选择已经停止并改用 5432。临时目录 `storage/postgres` 未投入使用，清理被自动审批策略阻止，因此暂时保留，启动脚本不会再启动它。

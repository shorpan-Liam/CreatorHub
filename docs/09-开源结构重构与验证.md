# 开源结构重构与验证

日期：2026-10-01。项目：CreatorHub。

## 目标与保留范围

采用开源工具库和 FastAPI 全栈模板的组织方式，拆开页面、业务状态、接口和渲染进程。页面使用白底、细边框、紧凑控件及红色操作强调。保留 Python + React + 本机 PostgreSQL，不引入 Docker、账号登录或外部文章处理服务。

原有入口保持为 `/`、`/tools/article-to-images`、`/help`、`/settings`。服务端截图入口仍为 `/_render`，API 前缀仍为 `/api/v1`，启动入口仍为根目录的 `一键启动.bat`。

数据库表、迁移历史、匿名会话 cookie、IndexedDB 的 `creatorhub` v1、localStorage 的 `creatorhub:` 前缀及草稿备份格式保持兼容。未清空用户草稿、边距收藏或数据库。重构前源码备份为 `storage/source-before-refactor-tree.zip`；备份不包含 `.env`、依赖、生成结果和本机草稿，恢复源码时需要保留现有这些数据。

## 前端结构

```text
frontend/src/
  app/                          路由、QueryClient、全局 Provider
  client/                       类型化客户端、错误边界、生成的接口类型
  components/
    layout.tsx                  页头与通用提示
    ui/                         图标按钮、错误边界
  features/catalog/             工具仓库、搜索、收藏、目录查询
  lib/storage.ts                兼容原版本的本机存储
  pages/Info.tsx                使用说明、本机设置
  tools/
    defineTool.ts               工具模块协议
    index.ts                    工具注册表
    article-to-images/
      meta.ts                   路由、封面、懒加载入口
      index.tsx                 工具工作区
      service.ts                类型化出图 API
      model.ts                  草稿、正文解析、业务校验
      rendering.ts              真实字体测量、分页、页面渲染
      hooks/                    草稿保存、编辑编排、服务端任务查询
      components/               内容、预览、设置、边距收藏、草稿弹窗
```

原顶层 `model.ts`、`rendering.ts`、`storage.ts` 保留兼容导出。文章页面不再包含所有业务和视图代码。TanStack Query 管理目录查询、请求取消与任务轮询；创建任务保留幂等标识，避免网络重试导致重复排队。

工具仓库使用 CSS 多列瀑布流，手机两列。当前只有一个已上线工具，不增加虚假的工具卡片。卡片封面由真实渲染服务生成并保存为静态 WebP。桌面工作区由内容、预览、可收起设置构成；中等屏幕设置为侧栏；手机保持内容、预览、版式页签。预览根据区域宽高等比缩放，完整展示 3:4 和 9:16 图片。

草稿弹窗和更多操作使用 Radix，图标使用 Lucide，图标工具提供名称提示。保留原有纯文本与 Markdown、署名和 Logo、自动与手动分页、两汉字首行缩进、左右 0–320px、上下 0–480px、首页顶部 0–720px、边距收藏、撤销重做、草稿冲突处理、备份导入导出、PNG/JPG、单页和 ZIP 下载、取消与过期提示。

## 后端结构

```text
backend/app/
  main.py                       应用组装、静态前端
  core/                         配置、数据库、错误处理、本机访问边界
  api/
    main.py                     汇总原有 /api/v1 路由
    deps.py                     SessionDep、OwnerDep
    responses.py                对外响应协议
    routes/                     健康检查、工具目录、会话、素材、出图
  services/                     素材处理、会话、任务提交及结果文件
  jobs/
    queue.py                    PostgreSQL 队列、租约、取消、过期清理
    renderer.py                 Chromium、字体、截图与 ZIP
    worker.py                   工作循环及心跳
    errors.py                   出图错误分类
  models.py                     原数据库模型
  schemas.py                    原输入校验
```

`app.config`、`app.db`、`app.worker` 保留兼容入口，因此启动、迁移、已有测试和脚本无需改用新命令。后端为素材、工具目录、模板、任务和错误增加了明确的响应模型，生成 TypeScript 接口类型，减少前后端字段不一致。

仍然使用 Python Playwright 导出。前端 Canvas 导出没有在本次替换现有引擎，因为它需要额外验证中文字体、CSS、跨域素材和长文分页一致性。启动仍检查 Chromium 是否能实际启动；页面加载、启动、截图错误保持独立错误码和本地日志。

## 开发命令

从项目根目录启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1
```

前端命令在 `frontend` 目录执行：

```powershell
npm run generate-client
npm run typecheck
npm test
npm run test:e2e
npm run format:check
npm run build
```

`generate-client` 调用项目 `.venv` 导出 FastAPI OpenAPI，不需要另开 API 服务或查询数据库，但需要已配置 `backend/.env`。`openapi.json` 和 `src/client/schema.gen.ts` 是生成文件，修改响应模型后应重新生成。端到端测试依赖 8000 端口的 API 与 Worker；浏览器上下文与用户浏览器隔离。服务端真实出图测试使用独立匿名会话提交测试文章。

后端测试在 `backend` 目录运行：

```powershell
../.venv/Scripts/python.exe -m pytest -q
../.venv/Scripts/python.exe -m ruff check app
../.venv/Scripts/python.exe -m ruff format --check app
```

测试继续使用专用 `creatorhub_test` 数据库。开发依赖安装命令为 `.venv/Scripts/python.exe -m pip install -r backend/requirements-dev.txt`。根目录 `scripts/check.ps1` 汇总后端 lint、格式、测试及前端格式、类型和单元测试；添加 `-E2E` 可同时运行桌面和手机端到端测试。真实渲染回归在根目录执行 `.venv/Scripts/python.exe scripts/verify_render.py`，包含中文、英文、组合字符、长段落、Logo、JPG、9:16、手动分页、只有标题及标题溢出。

工具卡片样例可在服务启动后运行 `.venv/Scripts/python.exe scripts/generate_tool_preview.py` 再重新构建前端。该脚本仅生成自己的测试文章并清理自己的匿名会话临时数据。

## 验证结果

- 23 项后端测试通过：原功能、并发任务认领、隔离、校验、迁移，以及新增接口兼容测试。
- 10 项前端单元测试通过：正文保留、草稿兼容、边距范围、目录搜索及收藏排序。
- 12 项 Playwright 端到端测试通过：桌面与手机分别验证目录、草稿恢复、撤销重做、边距收藏、首页独立留白、段落缩进、真实生成、ZIP、修改后结果失效、错误重试状态、弹窗和备份。
- 5 组真实渲染场景通过；校验原文 UTF-16 片段完整覆盖、图像尺寸和格式，以及 ZIP 内图片与单页文件一致。
- 已查看桌面与手机截图，没有发现横向溢出、标题遮挡或预览尺寸失真。验证截图位于 `storage/ui-verification/`。

这些验证覆盖本机 Chromium 和模拟移动视口。小红书、抖音真实上传后的裁切，以及 iOS/Android 相册保存，仍需实际 App 验证。

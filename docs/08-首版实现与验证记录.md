# 首版实现与验证记录

日期：2026-09-23 · 版本：0.1.0 · 当前状态：本机可运行

## 1. 已交付的功能

### 平台

- 无登录工具目录，名称/关键词搜索，类别及多平台筛选。
- 收藏、最近使用、本机默认品牌和草稿入口。
- 使用说明、本机数据管理、未知路由页面。
- 只有“文章转图片”作为可用工具，不展示虚构工具数量。

### 文章转图片

- 独立标题和正文、纯文本/Markdown 子集、显式标题换行。
- 默认保留原文，支持加粗、标题、引用、平级列表；不支持的格式按文本保留。
- `:::pagebreak` 显式分页，可通过按钮在光标位置插入，删除该行即取消。
- 每页个人署名、PNG/JPG/WebP Logo、圆形/原比例、默认品牌保存。
- 3:4 和 9:16 两个画布，标题/正文字号、行距、段距、留白、标题强调线、页码。
- 测量真实字体后按内容块分页，长段落使用安全字素边界切分、就近句末回退及孤行控制。
- 浏览器草图和服务端高清预览区分，内容变化时不再把旧图片当作当前结果。
- PNG/JPG 图片、单页下载、ZIP 打包；预览和下载使用同一批文件。
- IndexedDB 草稿、自动保存、立即离开页面时补充保存、最多 100 步会话撤销/重做。
- 草稿列表、复制、删除、项目 JSON 导入导出、多标签写入冲突提示。
- 任务进度、取消、幂等创建、失败提示、租约恢复、24 小时结果过期清理。

### 界面

采用淡暖色背景、深灰/灰绿色文字、细分隔线，不使用渐变和大阴影。桌面大屏三栏，中等宽度双栏加设置抽屉，手机分“内容 / 预览 / 版式”页签。导出按钮与下载结果分开，更多操作折叠。

## 2. 实际技术结构

- Python 3.11 / FastAPI / SQLAlchemy / psycopg / Alembic。
- React 19 / TypeScript / Vite / IndexedDB（idb）/ Zod。
- 使用用户现有 PostgreSQL 16 的 5432 端口；专用角色和应用/测试数据库。
- 独立 Python worker 领取 PostgreSQL 队列任务；Playwright Chromium 调用固定 React 渲染入口。
- 自托管 Noto Serif SC 字体，字体许可证随源码保留。
- 未引入 Docker、Redis、账号服务、模型调用或外部发布接口。

## 4. 相对设计文档的首版简化

1. 工具目录及模板元数据使用 JSONB 配置列，而非每个展示字段都单独建列；任务状态、时间和租约仍独立存储及索引。
2. render_outputs 用 page_number=0 表示 ZIP，正整数表示图片，以 `(job_id,page_number)` 唯一约束避免 NULL 重复。
3. 项目备份保存源文本、输入模式、原始文本快照、样式、Logo data URL 和版本。导入后重建内容块，不携带临时资源 ID、Cookie 或文件路径。
4. 首版正文编辑为 textarea + Markdown 子集，分段/合并通过文本编辑完成，没有复杂富文本工具栏。
5. 标题自动换行使用浏览器平衡换行，人工回车可控制断点；尚未实现设计中完整的中文短语候选评分算法。
6. 服务端排版版本绑定构建入口内容哈希；锁文件及构建资产哈希确定字体和组件版本。
7. worker 每 30 秒回收过期任务/资源，较设计文档的十分钟更及时；不增加独立清理服务。

以上简化保持主要产出流程，但不能将全部原始 P0 细则视为已完成验收。

## 9:16 首页列表裁切适配

9:16 输出尺寸仍为 1080×1920。按 3:4 列表卡片居中裁切模型，可见区域为 y=240 至 y=1680；首页额外顶部留白为 `(1920 - 1080×4/3) / 2 = 240px`，即图高的 12.5%。在默认 72px 页边距下，首页署名起点为 312px，显示署名时标题行框起点为 404px。署名、标题与正文整体下移，首页可用正文高度相应减少并重新分页；3:4 和后续页保持原布局。无标题、无署名的首页也遵循同一留白规则。

该居中裁切模型是兼容性假设，不是小红书所有客户端及入口的官方保证。公开封面资料支持使用 3:4，未找到官方统一裁切位置规范；发布前仍需在实际列表预览确认。参考：[小红书封面比例指南](https://xiaohongshu.oimi.ai/zh/blog/xiaohongshu-cover-size)。底部正文在列表缩略图中仍可能被裁切，完整内容保留在原始长图中。

预览和服务端出图共用 `frontend/src/rendering.ts`。已生成的旧图片不会自动修改，刷新网站并重新生成后生效。使用 `.venv\Scripts\python.exe scripts/verify_cover.py` 验证 8 组真实 Chromium 排版组合：两种比例、有无标题、有无署名，检查首页留白、续页位置、画布尺寸、正文覆盖及溢出；同时输出 `storage/cover-verification/cover.png` 与 `feed-card.png` 供视觉检查。

## 手动边距与收藏版本（当前规则）

本节替代上方“9:16 首页列表裁切适配”：已撤回首页自动增加 240px 的规则。所有比例均默认使用用户设置的上下边距。

- 编辑器“内容边距”支持滑块和数字输入，步长 1px：左右 0–320px，上下 0–480px。
- 可勾选“首页顶部单独调整”，设置 0–720px 的绝对顶部留白；默认关闭。仅首页顶部使用该值，续页及首页底部仍使用通用上下边距。
- 边距过大导致标题无法容纳时沿用排版错误提示，不会截断正文；可减少留白、缩小字号或开启标题自动适配。
- 命名后“收藏当前边距”，下次选择收藏并点击“套用”。支持最多 30 套、同名确认覆盖、删除；套用只改变三项边距，不修改文章、字号、比例或品牌。
- 收藏保存于当前浏览器 IndexedDB preferences；刷新与下次打开保留，不跨浏览器同步，清除本机数据会删除。草稿备份保存当前边距，但不包含整个收藏库。
- `firstPagePaddingTop` 为可选的 nullable 整数字段，旧草稿、备份和 API 请求缺失该字段时默认为 null，兼容旧数据。后端同步扩大边距校验范围。

验证：前端 8 项测试、后端边距边界测试通过；真实 Chromium 16 组首页/续页排版检查通过；5 组 API/worker 出图回归通过。浏览器完成收藏、刷新恢复、改变参数后套用及自定义边距高清出图验证。

## 2026-09-30 Playwright 浏览器检查

本次错误的直接原因是 worker 启动 Chromium 时找不到 `chromium_headless_shell-1243` 的可执行文件；这表示 Playwright 浏览器包当时安装不完整或安装过程尚未完成，并非项目文章、字体或数据库内容问题。当前 `.venv` Python 3.11 的 Playwright 1.63.0 已重新执行 `python -m playwright install chromium`，主 Chromium 与 headless shell 均可启动。

`start.ps1` 现在启动 API 前执行 `scripts/check_renderer.py`，会真实启动一次 Chromium；检查失败会在启动阶段提示安装命令，不再等到生成图片时才失败。worker 同时保留浏览器启动、页面加载和截图阶段的分类错误及本机日志。验证：健康检查通过，5 组真实 API/worker 出图通过，worker 日志显示 4 个成功任务。

# 数据模型与 API 契约

版本：0.1 · API 前缀：`/api/v1` · 数据格式：UTF-8 JSON

本文保留开发前契约，首版接口已实现。运行时 OpenAPI 位于 `/docs`，首版简化见 `08-首版实现与验证记录.md`；后续变更同步更新契约与前端类型。

## 1. 通用约定

- ID 使用服务端生成的 UUID；时间使用 UTC RFC 3339 字符串，前端按本地时区显示。
- JSON 字段采用 camelCase，数据库字段采用 snake_case。
- revision 是本机单稿单调增加的整数；draftId 只关联本机草稿，不提供访问授权。
- 需隔离的资源使用匿名 HttpOnly Cookie，接口不用 userId，也不接受前端自报 ownerId。
- 错误格式：`{"error":{"code":"PAGE_LIMIT_EXCEEDED","message":"内容超过 50 页，请拆分文章","details":{"limit":50},"requestId":"..."}}`。
- 未知/非本人资源均返回 404；已过期且归属明确的结果返回 410。
- 业务校验返回 422；体积超限 413；冲突 409；限流/队列已满 429 并带 Retry-After；服务不可用 503。
- 文件接口不放进公共静态目录，必须经授权处理器输出。

## 2. 工具目录数据

```json
{
  "slug": "article-to-images",
  "name": "文章转图片",
  "description": "把文章排成带个人品牌的高清图文卡片",
  "category": "graphic-content",
  "platforms": ["xiaohongshu", "douyin", "zhihu"],
  "keywords": ["长文", "分页", "图文", "小红书"],
  "status": "available",
  "route": "/tools/article-to-images",
  "iconKey": "article-images",
  "sortOrder": 10
}
```

slug 由种子数据管理且唯一，路由和 iconKey 来自受控映射，不允许数据库注入任意脚本或外部地址。目录前端一次加载后本地搜索筛选，首版不需要复杂搜索引擎。

## 3. 文章与渲染快照

```json
{
  "schemaVersion": 1,
  "draftId": "local-uuid",
  "revision": 7,
  "document": {
    "title": "让内容创作\n更顺手",
    "sourceFormat": "plain",
    "sourceText": "一段原创示例正文。\n\n第二段。",
    "blocks": [
      {"id":"b1","type":"paragraph","runs":[{"text":"一段原创示例正文。","bold":false}]},
      {"id":"b2","type":"page_break"},
      {"id":"b3","type":"paragraph","runs":[{"text":"第二段。","bold":false}]}
    ]
  },
  "brand": {
    "name": "小潘同学",
    "showName": true,
    "showLogo": false,
    "logoAssetId": null,
    "logoShape": "circle",
    "fontSize": 28
  },
  "layout": {
    "templateId": "classic-reading",
    "templateVersion": 1,
    "preset": "portrait-3-4",
    "width": 1080,
    "height": 1440,
    "titleFontSize": 104,
    "titleAutoFit": false,
    "bodyFontSize": 40,
    "lineHeight": 1.7,
    "paragraphGap": 36,
    "paddingX": 80,
    "paddingY": 72,
    "titleUnderline": true,
    "showPageNumber": true
  },
  "output": {"format":"png"}
}
```

### 内容块类型

| 类型 | 字段 | 规则 |
| --- | --- | --- |
| paragraph | id、runs | 常规段落 |
| heading | id、level、runs | 首版正文仅允许 level=2 或 3 |
| quote | id、runs | 引用视觉样式，不执行引用内容 |
| list_item | id、listId、ordered、ordinal、runs | 平级列表；ordinal 为正整数；续页前缀不重复 |
| page_break | id | 显式分页，无正文 |

runs 为 text + bold；text 可包含显式软换行，不接受 HTML。段内样式暂不支持链接点击、任意颜色或任意字体。源文本仅供恢复和比对，不在 worker 中重新解释，渲染基于已确认 blocks。

### 校验及版本

- 请求主体最大 2 MiB（不含已独立上传的图片）；可见正文总长度 ≤20,000 码点，标题 ≤100，品牌 ≤24。
- sourceText 上限 100,000 码点，防止滥用源快照字段；blocks 最多 2,000、总 runs 最多 10,000。
- 空标题 + 无可见正文禁止生成；仅标题允许。所有块 ID 唯一，重复返回 422。
- 画布仅允许两个预设，preset 与尺寸不匹配返回 422，不允许请求任意超大画布。
- 服务端追加 rendererVersion、layoutVersion、fontManifestHash；渲染哈希包含这些版本、可见内容、样式、格式和 Logo 内容哈希，不依赖短期 assetId 本身。
- snapshot 存提交时完整校验后的值，此后不可编辑。后续编辑创建新任务。
- `.creatorhub.json` 为不同的备份封装，含上述配置及 `embeddedAssets`（base64 与 MIME），移除 logoAssetId、服务端任务和临时 URL；导入时还原本机 Blob，渲染时再上传。

## 4. 分页清单

```json
{
  "layoutVersion": "1",
  "pageCount": 2,
  "pages": [
    {"page":1,"fragments":[{"blockId":"b1","startUtf16":0,"endUtf16":9}],"warnings":[]},
    {"page":2,"fragments":[{"blockId":"b3","startUtf16":0,"endUtf16":4}],"warnings":[]}
  ]
}
```

上例范围对应示例正文长度；实际布局以渲染测量生成。每块多个 runs 的可见文本先拼接后定位，UTF-16 半开区间覆盖实际字符；分页标记、标题、品牌、页码由独立布局字段处理。标题同样要验证完整展示，但不重复混入正文范围。

警告包含 code、blockId、page、message；可降级警告与阻断错误分别输出。字符覆盖检查必须结合图像边界检测，不能仅靠 sourceRange 存在判断视觉已绘制成功。

## 5. PostgreSQL 表设计

所有时间字段为 timestamptz。初版不建 users 或 server_drafts 表。

| 表 | 主要字段 | 约束和索引 |
| --- | --- | --- |
| tools | slug PK、name、description、category、platforms JSONB、keywords JSONB、status、route、icon_key、sort_order、updated_at | status CHECK；排序索引 |
| templates | id、version、name、config JSONB、font_manifest JSONB、active | 复合 PK(id,version)；版本不可覆盖修改 |
| anonymous_sessions | id UUID PK、token_hash、created_at、last_seen_at、expires_at | token_hash UNIQUE；expires_at 索引 |
| assets | id UUID PK、session_id FK、storage_key、sha256、mime_type、byte_size、width、height、created_at、expires_at | (session_id,id)、expires_at；storage_key UNIQUE |
| render_jobs | id UUID PK、session_id FK、idempotency_key、request_hash、render_hash、snapshot JSONB、status、stage、progress_current、progress_total、attempts、available_at、lease_token、lease_expires_at、worker_id、heartbeat_at、created_at、started_at、finished_at、expires_at、error_code、error_detail、layout_manifest JSONB | UNIQUE(session_id,idempotency_key)；领取索引(status,available_at,created_at)；过期索引 |
| render_job_assets | job_id FK、asset_id FK | 联合 PK；资产引用保留检查 |
| render_outputs | id UUID PK、job_id FK、attempt、kind、page_number、storage_key、mime_type、byte_size、sha256、width、height | job/kind/page 唯一；kind=page 或 archive；archive 页码 NULL |
| worker_heartbeats | worker_id PK、last_seen_at、renderer_version、state | last_seen_at 索引 |

archive 的唯一性使用部分唯一索引，避免 NULL 导致重复 ZIP。page_number 从 1 开始。JSONB 中也存 schemaVersion，Pydantic 在写入前执行严格校验；常用状态与时间独立列，不在 JSON 中查询队列状态。

终态满 24 小时：删除产物和快照、layout_manifest 及资产引用；保留任务 ID、耗时、状态及错误码作为 7 天最小元数据，snapshot 置 NULL，并设置结果过期标识。接口据 expires_at 返回 410。满 7 天删除任务记录，之后返回 404。

物理文件删除与数据库事务无法原子完成，应采用可重试清理：先标记资源不可读，再删文件，最后清理行；删除失败留待重试。渲染结果发布使用反向顺序：文件准备完成后才能在事务中标记 succeeded。

## 6. API 列表

| 方法 | 路径 | 请求/响应 | 说明 |
| --- | --- | --- | --- |
| GET | `/health/live` | `{status:"ok"}` | 进程存活，不触发 DB 写入 |
| GET | `/health/ready` | DB/worker 可用摘要 | 不可执行渲染时 readiness=degraded 或 503，详情不含凭证 |
| GET | `/tools` | `{items:[Tool]}` | 排除 hidden，排序稳定 |
| GET | `/templates?tool=article-to-images` | 模板列表和允许配置 | 仅公开受控参数，无任意脚本 |
| POST | `/session` | 204 + Set-Cookie | 已有效会话续期，不更换 token；幂等创建体验 |
| POST | `/assets` | multipart file → 201 Asset | 需会话，校验/解码/清理图片元数据 |
| GET | `/assets/{id}/content` | image bytes | 归属校验，支持预览，过期 410 |
| DELETE | `/assets/{id}` | 204 | 活动任务引用返回 409；无引用则删除 |
| POST | `/renders` | Snapshot → 202 Job | 必填 Idempotency-Key；创建快照及 queued 任务 |
| GET | `/renders/{id}` | Job 状态、进度、诊断、输出列表 | 包含 revision、renderHash、expiresAt |
| POST | `/renders/{id}/cancel` | 200 Job | 重复取消幂等，终态不倒退 |
| GET | `/renders/{id}/pages/{page}` | 对应 PNG/JPG | 可 `?download=1` 添加附件响应头 |
| GET | `/renders/{id}/archive` | ZIP | 仅完整 succeeded、未过期可下载 |
| DELETE | `/session/data` | 202 清理状态 | 取消活动任务、标记临时数据清理；不删浏览器草稿 |

首版无草稿 CRUD API、无发布 API、无 AI API。项目备份在浏览器生成和读取。

### 6.1 创建任务示例响应

```json
{
  "id": "job-uuid",
  "status": "queued",
  "stage": "queued",
  "revision": 7,
  "renderHash": "sha256:...",
  "progress": {"current":0,"total":null},
  "createdAt": "2026-09-23T04:00:00Z",
  "expiresAt": null,
  "outputs": []
}
```

终态后才确定 expiresAt。成功响应 outputs 含 page、width、height、bytes、sha256、url，并提供 archiveUrl 和 warnings。URL 仅为路径，仍受 Cookie 归属控制。

### 6.2 轮询与重复请求

首版 1 秒查询一次；持续 10 秒后退避到 2 秒；后台页签可退避到 5 秒。用户离开工具页停止轮询；重新进入可查询记录的 jobId。终态停止轮询。网络超时重发 POST 时必须复用原 Idempotency-Key，而用户主动“重新生成”使用新 key。

## 7. 任务状态与阶段

```text
queued → running → succeeded
   │        ├──→ failed
   │        ├──→ cancel_requested → cancelled
   └──→ cancelled

running --临时故障/租约回收且未超重试数--> queued
```

stage 可为 queued / validating / loading / paginating / rendering / packaging / finished。有真实总页数之后才展示按页进度；打包阶段不伪造完成百分比。

expired 是结果可用性，不是覆盖任务执行结果的状态。已成功任务过期后历史 status 仍为 succeeded，GET 返回结果过期信息，不允许再下载。取消与成功并发由状态条件更新决定：已进入 cancel_requested 的任务不能提交成功。

## 8. 主要错误码

| code | 典型 HTTP | 用户动作 |
| --- | --- | --- |
| EMPTY_DOCUMENT | 422 | 输入标题或正文 |
| CONTENT_TOO_LONG / TITLE_TOO_LONG | 422 | 缩短或拆分文章 |
| UNSUPPORTED_SCHEMA_VERSION | 422 | 使用受支持版本重新导出项目 |
| UNSUPPORTED_ASSET_TYPE / ASSET_DECODE_FAILED | 422 | 换用有效 PNG/JPEG/WebP |
| ASSET_TOO_LARGE | 413 | 压缩图片后上传 |
| ASSET_EXPIRED | 410 | 从本机 Logo 重新上传 |
| IDEMPOTENCY_CONFLICT | 409 | 新操作使用新 key |
| SESSION_QUEUE_LIMIT / GLOBAL_QUEUE_FULL | 429 | 等待已有任务完成 |
| TITLE_OVERFLOW / BLOCK_OVERFLOW | 异步任务失败 | 根据定位调整内容或样式 |
| PAGE_LIMIT_EXCEEDED | 异步任务失败 | 拆为多篇文章 |
| FONT_LOAD_FAILED / RENDER_TIMEOUT | 异步任务失败 | 查看提示后重试，必要时修复环境 |
| CONTENT_COVERAGE_FAILED | 异步任务失败 | 报告缺陷；禁止发布不完整结果 |
| RESULT_EXPIRED | 410 | 从草稿重新生成 |
| DATABASE_UNAVAILABLE / WORKER_UNAVAILABLE | 503 或任务失败 | 保留草稿、恢复服务 |

异步任务失败通过 GET Job 的 error 对象表达，GET 本身仍为 200；不能混淆“查询请求成功”和“渲染成功”。

## 9. 数据库迁移及种子

- Alembic 建表；种子数据命令幂等写入一个可用工具和一个模板版本。
- 不在每次 API 启动时自动创建/删除所有表；迁移通过明确命令执行。
- 升级模板新增版本，旧版本保留至所有有效任务完成；旧草稿请求失去支持的版本时提示迁移，不静默替换。
- 测试使用独立 `creatorhub_test` 数据库，任何清理动作拒绝指向非测试数据库。

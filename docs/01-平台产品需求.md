# CreatorHub 平台产品需求文档

版本：0.1 · 日期：2026-09-23 · 状态：开发基线

## 1. 产品定位

CreatorHub 是面向自媒体创作者的工具聚合入口，帮助用户完成从内容整理到素材产出的重复工作。目标平台包括小红书、抖音、知乎，后续可增加公众号、视频号、B 站等平台标签。

首版定位为“有一个高质量内置工具的可扩展工具仓库”，通过统一工具目录、收藏、最近使用和工作区形成长期入口。平台标签表示适用场景，不表示已取得平台接口授权或与其建立官方合作。

品牌名称固定为 CreatorHub；建议中文说明：自媒体人的一站式工具库。

## 2. 目标用户与问题

| 用户 | 典型工作 | 当前问题 | 平台价值 |
| --- | --- | --- | --- |
| 个人知识博主 | 将观点长文做成图文笔记 | 逐页复制、字号不一致、分页费时 | 一次输入、统一排版、批量导出 |
| 多平台创作者 | 同一篇内容适配不同平台 | 工具散落、重复寻找 | 按平台和任务快速定位工具 |
| 运营人员 | 为固定品牌持续制作内容 | 每次重新设置头像、署名和样式 | 本机记忆品牌及常用设置 |
| 偶尔创作的用户 | 临时制作一组图片 | 不想注册、不熟悉设计工具 | 模板默认可用、操作路径短 |

## 3. 产品目标与衡量方式

- 新用户进入首页后能直接识别可用工具，无登录弹窗。
- 从粘贴一篇约 1,500 字文章到下载成品，目标在 3 分钟内完成，人工阅读和深度修改时间除外。
- 自动分页不丢字、不重复、不裁掉文字；长内容增加页数而非无限缩小字号。
- 预览和导出能够对应到同一内容版本，编辑之后明确显示旧结果已过期。
- 首版以本机体验及任务成功日志验证，不引入第三方追踪 SDK。

验收目标与性能基线见 `06-开发计划与验收.md`；以上不是已测量结果。

## 4. 信息架构

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 工具首页 | `/` | 品牌、搜索、类别、平台筛选、收藏、最近使用、工具卡片 |
| 文章转图片 | `/tools/article-to-images` | 内容编辑、样式设置、分页预览、下载 |
| 使用说明 | `/help` | 工具流程、本地保存说明、常见失败及排查 |
| 本机数据设置 | `/settings` | 默认品牌、清除本机数据、备份提示 |
| 未找到页面 | `/*` | 返回工具库、保留其他草稿 |

首版工具直接从卡片进入编辑器，不增加无必要的工具详情中转页。桌面和手机共享 URL。

## 5. 平台功能清单

| ID | 优先级 | 功能 | 详细规则与验收 |
| --- | --- | --- | --- |
| HUB-001 | P0 | 无登录访问 | 所有首版工具无需账号；浏览工具目录不创建草稿或渲染任务 |
| HUB-002 | P0 | 工具卡片 | 展示名称、用途一句话、分类、平台标签、可用状态；点卡片进入工具 |
| HUB-003 | P0 | 搜索 | 对名称、描述、关键词匹配，不区分英文大小写，忽略两端空白；空查询显示全部 |
| HUB-004 | P0 | 类别与平台筛选 | 类别单选；平台多选时组内 OR，类别、平台、搜索之间 AND；“通用”工具匹配任意平台 |
| HUB-005 | P0 | 收藏 | 按工具 slug 在本机保存，刷新仍保留；取消收藏即移除，不影响草稿 |
| HUB-006 | P0 | 最近使用 | 成功打开工具才记录，按最后使用排序，去重保留 12 项 |
| HUB-007 | P0 | 可用状态 | `available` 可使用，`planned` 显示规划中且无虚假启动按钮，`hidden` 不在目录出现 |
| HUB-008 | P0 | 无结果状态 | 展示当前筛选条件与清除筛选操作；不编造匹配结果 |
| HUB-009 | P0 | 默认品牌 | 保存名称、可选 Logo、显示偏好；新作品继承，旧作品不被批量修改 |
| HUB-010 | P0 | 草稿恢复入口 | 对文章转图显示本机最近草稿，用户可恢复或新建，不静默覆盖 |
| HUB-011 | P0 | 通用反馈状态 | 加载、保存中、已保存、导出中、失败、离线状态可区分 |
| HUB-012 | P0 | 响应式与键盘操作 | 390px 手机可完成主流程；桌面三栏；可见焦点、表单标签、合理点击区域 |
| HUB-013 | P0 | 本机数据管理 | 可查看草稿列表、删除单稿、清空偏好；清空操作列明影响范围并确认 |
| HUB-014 | P0 | 工具注册机制 | 单一目录数据源，统一 slug、类别、标签、状态、路由；无管理后台 |
| HUB-015 | P1 | 外部工具导航 | 明确外链标识，用户主动打开；不把文章自动传给外部站点 |
| HUB-016 | P1 | 工具反馈入口 | 在确定接收方式后实现，不提前加入无效表单 |
| HUB-017 | P2 | 跨工具工作流 | 支持文章、标题、图片等公共产物在多个工具之间传递 |

目录首次上线只有“文章转图片”标记可用。首页以真实工具展示为主，规划项可放在单独的折叠区域，不制造工具很多的假象。

## 6. 工具分类与扩展候选

| 分类 | 候选工具 | 场景 | 阶段 |
| --- | --- | --- | --- |
| 图文制作 | 文章转图片 | 小红书文字笔记、观点卡片 | P0 |
| 图片处理 | 封面制作、图片压缩、比例调整 | 多平台素材 | P1 候选 |
| 文案辅助 | 标题候选、内容结构整理 | 小红书、知乎、抖音文案 | P1 候选 |
| 内容适配 | 长文转短稿、图文转口播稿 | 跨平台复用 | P2 |
| 视频辅助 | 字幕整理、口播提词 | 抖音等短视频平台 | P2 |

此表是产品方向，不构成首版开发承诺。每个新工具应补充独立需求与验收用例后再开发。

## 7. 无登录的数据体验

- 收藏、最近使用保存在 localStorage；正文草稿、品牌图片和作品配置保存在 IndexedDB。
- 页面明确说明“草稿保存在当前浏览器”，不使用“云同步成功”文案。
- 渲染时文章和 Logo 会提交到本地 Python 服务；未来公开部署时服务将位于站点服务器，应同步修改提示，不能继续宣传全部本机处理。
- 后端以匿名会话隔离临时素材及任务；不要求姓名、邮箱、手机号。
- 用户清理浏览器数据、更换浏览器或设备后无法自动恢复，提供项目备份文件解决迁移。
- 导出成品和服务器临时数据默认保留 24 小时，浏览器草稿保留到主动删除；“清除本机数据”不隐含已删除全部服务器任务，提供单独清理动作。

## 8. 交互原则

1. 工具页面以产出任务为中心，不向普通用户展示数据库、渲染进程等实现概念。
2. 主按钮明确表达动作，例如“生成预览”“下载全部图片”，而非模糊的“提交”。
3. 长任务可查看阶段并取消；百分比仅在有真实总量时显示。
4. 故障不清空编辑内容；失败消息说明可执行的恢复动作。
5. 首版以清晰白底、适量色彩、突出内容为方向，最终界面在开发设计阶段确定。
6. 参考截图仅用于版式分析；不复制小红书的关注、点赞、评论等 App 外壳，不使用截图文章作为默认示例文案。

## 9. 首版不包含

用户账号、会员支付、团队协作、后台运营系统、平台账号绑定、自动发布、数据抓取、热点监控、自由拖拽画布、多模态素材生成。AI 不影响无 AI 的主流程。

## 10. 关键产品决定

| 决定 | 原因 |
| --- | --- |
| 平台与工具分层 | 首个工具深入做好，后续工具可独立扩展 |
| 本机草稿 + 服务器临时任务 | 保持无登录体验，减少长期保存文章的复杂度 |
| 先原文排版、后 AI | 避免文案被静默改写，确保导出能力不依赖模型服务 |
| 不保证全景展示 | App 客户端、上传方式和展示页面可能有不同裁切行为 |
| 本地 Python + React + PostgreSQL | 遵循已确认技术栈，无 Docker、无额外任务中间件 |
